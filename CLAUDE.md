# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An extended Kalman filter (EKF) library for 3D localization and SLAM (simultaneous localization and mapping), built on numpy/scipy. Package name is `ekf_slam_3d` (PyPI: `ekf-slam-3d`), dependency-managed with uv.

## Commands

Uses uv + a Taskfile (go-task). Python 3.13 required. Runtime deps live in `[project.dependencies]`; test/dev tooling (pytest, pytest-cov, pre-commit) is in the `dev` group under `[dependency-groups]`.

```bash
task init    # uv sync
task demo    # alias for demo:slam; also demo:mapping, demo:localization (need a real display)
task demo:slam -- --scenario <name>   # run one SLAM dataset from examples/slam_scenarios.py
task demo:slam3d                      # 3D SLAM (baseline_3d)
task format  # ruff format, ruff check --fix, mypy over ekf_slam_3d/ tests/ config/ examples/
task test    # pytest with coverage over ekf_slam_3d/ (term-missing report, no-cov-on-fail)
task clean   # remove .venv, caches, build/dist artifacts
```

Run a single test:
```bash
uv run pytest tests/modules_tests/kalman_test.py::test_name
```

Run one of the example pipelines directly (also invocable via `__main__.py -p {KF,EKF,MAPPING,SLAM,STATE_SPACE}`):
```bash
uv run python examples/ekf_localization_example.py  # pose only, map known
uv run python examples/ekf_mapping_example.py        # map only, pose known
uv run python examples/ekf_slam_example.py           # pose + map, both unknown
```

Pre-commit hooks (flake8, mypy, ruff, ruff-format) run on commit; the `pytest` hook is skipped in CI (`.pre-commit-config.yaml`). `ruff` and `mypy` are pinned in the `dev` dependency group (matching the versions used by `.pre-commit-config.yaml`) so `task init` installs them into `.venv` and `uv run ruff`/`uv run mypy` resolve without relying on a `PATH` install.

## Architecture

Two-layer design: `ekf_slam_3d/data_classes/` holds state/geometry representations and measurement models; `ekf_slam_3d/modules/` holds the estimation/control algorithms that operate on them. `config/definitions.py` centralizes all tunable constants (noise sigmas, plotting, epsilon for numerical differentiation, etc.) — new constants belong there, not inline.

**Noise conventions:** `MEASUREMENT_NOISE`, `SIGMA_VEL` and `SIGMA_OMEGA` are *standard deviations* — the simulated sensors add `N(0, MEASUREMENT_NOISE)` to distance and `N(0, MEASUREMENT_NOISE / (1 + distance))` to azimuth. Anything handed to a filter or to `SlamSimulator` as `process_noise` is a *covariance* (`CONTROL_NOISE_COVARIANCE = diag(SIGMA_VEL², SIGMA_OMEGA²)`; the simulator injects `N(0, sqrt(diag(Q)))`). The EKF's scalar `measurement_noise` is a *variance* (`R = measurement_noise * I`), so pipelines pass `MEASUREMENT_NOISE**2`; mapping/SLAM additionally pass `distance_azimuth_covariance(z, MEASUREMENT_NOISE)` so the filter's noise model matches the simulator. Mixing up std and variance here previously left the filter with badly wrong noise and a rigidly offset map.

**State representation** (`data_classes/lie_algebra.py`): `SE3` is the pose class (x, y, z, roll, pitch, yaw), convertible to/from a 6-vector and a 4x4 homogeneous transform via `as_vector()`/`as_matrix()`. `state_to_se3()` converts the first 6 elements of any state vector into an `SE3`. All state vectors elsewhere in the codebase are numpy column vectors (shape `(n, 1)`), with pose occupying indices `0:6`.

**Map/measurement layer** (`data_classes/map.py`, `data_classes/sensors.py`): `Feature`/`Map` hold landmark positions. `sensors.py` defines the known-map measurement functions (`measure_gps`, `measure_distance`, `measure_azimuth`, `measure_elevation`, `measure_distance_azimuth`, `measure_distance_azimuth_elevation`) that all share the signature `(state, features, noise=None) -> np.ndarray`, and `step_dynamics()`, the nonlinear motion model (bicycle-style kinematics). The `Sensor` enum wires sensor names to their measurement functions so filters can be handed `Sensor.X.func` generically. `PoseMap` (`data_classes/slam.py`) packs pose + map features into a single EKF state vector for SLAM (pose in `0:6`, then interleaved feature x/y pairs) via `as_vector()`/`from_vector()`.

For mapping/SLAM, the map is no longer a fixed external argument — landmark positions live inside the EKF state, so the corresponding measurement/motion functions read them back out of the (possibly perturbed) state vector instead of a captured closure, which keeps `StateSpaceNonlinear`'s finite-difference Jacobian correct with respect to landmark position too:
- `measure_distance_azimuth_map(state, args=(pose, feature_ids, num_landmarks), noise=None)` / `step_dynamics_map`: state is landmark positions only (2 per landmark), pose is known and passed in via `args`.
- `measure_distance_azimuth_slam(state, args=(feature_ids, num_landmarks), noise=None)` / `step_dynamics_slam`: state is `[pose(6); landmarks(2N)]`, both estimated together.
- `initialize_landmark_estimate(pose, distance, azimuth)` inverts a single range-azimuth sighting into a landmark's (x, y). `inverse_distance_azimuth_slam` (pose read from the state) and `inverse_distance_azimuth_map` (pose passed in) wrap it as inverse observation models for `ExtendedKalmanFilter.initialize_from_measurement()`, which is how new landmarks enter the state. Never seed a landmark by writing `ekf.x`/`ekf.cov` directly: without its cross-covariance to the pose, a landmark seeded from a drifted pose is treated as an independent, well-known reference, so the filter bends the pose to fit it and the whole map stays rigidly offset (with markers that barely move).
- 3D SLAM: `measure_distance_azimuth_elevation_slam` (state is `[pose(6); landmarks(3N)]`, interleaved x/y/z), `step_dynamics_3d` / `step_dynamics_slam_3d` (controls `[velocity, yaw rate, pitch rate]`; the vehicle climbs along its pitch — `step_dynamics` is exactly `step_dynamics_3d` with zero pitch rate), and `initialize_landmark_estimate_3d` / `inverse_distance_azimuth_elevation_slam`. Azimuth and elevation are both taken in a level, yaw-aligned sensor frame (elevation = `atan2(dz, horizontal distance)`, in [-pi/2, pi/2]), so roll/pitch don't enter the measurement.
- `features_in_range(pose, features, max_range)` models the limited sensor range (3D distance); `distance_azimuth_covariance(readings, noise, stride)` returns the covariance matching the simulated range-azimuth (stride 2) or range-azimuth-elevation (stride 3) noise; `angle_mask(length, stride, offsets)` flags the angle-valued entries of an interleaved measurement, and `ANGLE_LAYOUTS` records each angle-bearing measurement function's layout — register any new one there so `update()` wraps its angles automatically.

**Estimation layer** (`modules/`):
- `state_space.py`: `StateSpaceLinear` (A/B/C/D matrices, `step`, `continuous_to_discrete` via `scipy.signal.cont2discrete`) and `StateSpaceNonlinear`, which wraps an arbitrary motion-model callable and numerically linearizes it (central-difference Jacobian, see `EPSILON` in `config/definitions.py`) to produce local A/B matrices — this is what makes the EKF "extended".
- `kalman.py` / `kalman_extended.py`: `KalmanFilter` operates on a `StateSpaceLinear`; `ExtendedKalmanFilter` operates on a `StateSpaceNonlinear`, re-linearizing the motion model on `predict()` and the given sensor function on `update()` (the sensor function itself is passed into `update()`, enabling multi-sensor fusion with a single filter instance). Both keep covariance symmetric via `math_utils.symmetrize_matrix()` after every step. `update()` takes an optional `MeasurementSpec(covariance=..., angle_mask=...)`: `covariance` overrides `measurement_noise * I`, and `angle_mask` marks the angle-valued entries of `z` (azimuth/elevation), whose innovations are wrapped to `[-pi, pi)` with `math_utils.wrap_to_pi()` — otherwise a bearing straddling the atan2 branch cut is misread as a ~2*pi error and slams the pose estimate. It defaults to `sensors.default_angle_mask(sensor, len(z))`, so it only needs passing for sensors not in `ANGLE_LAYOUTS`. `initialize_from_measurement(idx, z, inverse_model, ...)` seeds a pre-allocated state block (a landmark) with covariance `G_x P G_x^T + G_z R G_z^T` and cross-covariance `G_x P`, Jacobians taken numerically by `StateSpaceNonlinear.linearize` with `z` in place of the control.
- `controller.py`: LQR / pole-placement control (`LQRController`, `full_state_feedback`), independent of the filtering code — used to drive simulated trajectories (e.g. `get_angular_velocities_for_box` for open-loop box paths). `box_path` builds one noise-free rounded-box loop (point spacing = `ROBOT_SPEED * DELTA_T`, corners scaled by `DELTA_T`), `pure_pursuit_turn_rate` steers along it, and `pitch_rate_toward_path` pitches toward the lookahead point's altitude (3D paths are `(N, 3)`); the SLAM pipeline steers on the EKF's *estimate*, closed-loop, because open-loop control noise lets the true robot wander far off the map.
- `simulators.py`: `SlamSimulator` drives ground-truth motion, live pyqtgraph visualization (pose, covariance ellipse, measurement rays, and optionally estimated landmarks with uncertainty ellipses via `append_result(landmarks=[LandmarkEstimate(...)])`), and feeds measurements to a filter in the example pipelines. The plot widget (`sim_plot`) is created lazily on first use, so headless/test runs with `show_plot=False` never touch Qt. pyqtgraph auto-ranging is disabled; the view only grows (`expand_view_bounds`) to fit the robot plus what is known — the whole map if `map_known=True` (localization), otherwise only the landmarks estimated so far. Pure helpers (`expand_view_bounds`, `ellipse_geometry`) are unit-tested without Qt.
- `math_utils.py`: standalone linear-algebra/rotation helpers (`skew_matrix`, `matrix_exponential` via eigendecomposition or Jordan form for non-diagonalizable matrices, `align_to_gravity`, `wrap_to_pi`, IMU-style dead-reckoning helpers).

**Entry point** (`__main__.py`): a `Pipeline` enum (`KF`, `EKF`, `MAPPING`, `SLAM`, `CONTROLLER`, `STATE_SPACE`) dispatches to scripts under `examples/` via subprocess. `EKF` estimates pose only (map known), `MAPPING` estimates the map only (pose known), `SLAM` estimates both together from range-azimuth sightings alone. The localization and mapping pipeline functions return `(ekf, ...)`; the SLAM pipeline returns a `SlamRun` (the EKF plus per-step true/estimated poses, known-landmark counts, and each landmark's error/covariance at first sighting), so accuracy can be asserted directly in tests rather than only eyeballed from the live plot.

**SLAM datasets** (`examples/slam_scenarios.py`): `SlamScenario` defines a map (landmarks evenly spaced, with jitter, around a square — unlike uniform random placement, this reliably puts every landmark in range at some point and gives the start pose landmarks to anchor to; the scenario tests assert both) and a closed loop centered on it; `SCENARIOS` holds named datasets (`baseline`, `clockwise`, `branch_cut`, `long_run`, `sparse`, `dense`, `offset_map`), each targeting a bug class. 3D scenarios set `three_d=True` (plus `landmark_heights`, `altitude`, `altitude_swing`); `SlamScenario.landmark_dim` is 2 or 3, and the pipeline picks the `PLANAR` or `SPATIAL` `SlamModel` (motion, sensor, inverse, and control-noise models; readings per landmark = `landmark_dim`). 3D-only random draws (landmark heights) happen only for 3D scenarios, so seeded planar datasets are unaffected. `ekf_slam_example.pipeline(show_plot, scenario)` senses *before* the first move (anchoring the map to the exactly-known start pose, `START_POSE_VARIANCE`), then each step: steer on the estimate, move, update with already-known visible landmarks, then seed newly visible ones. To add a dataset, add a `SlamScenario` to `SCENARIOS` — it's automatically covered by every scenario test.

Tests in `tests/` mirror the `ekf_slam_3d/` package layout (`data_classes_tests/`, `modules_tests/`), plus `tests/examples_tests/` which mirrors `examples/`: each pipeline gets a seeded, synthetic-dataset accuracy test (deterministic RNG seed, bounded step count) asserting the final pose/map estimate is within a numeric tolerance of ground truth, rather than only being visually inspected via the live plot. `ekf_slam_example_test.py` is parametrized over every scenario and checks: progressive discovery, final pose/landmark accuracy, map shape after best-fit rigid alignment (separates shape bugs from the unobservable global frame), no per-step yaw or pitch jumps (catches unwrapped bearings, 3D model mismatches), altitude tracked at every step (3D only), landmark NEES bound (catches overconfidence, e.g. seeding without cross-covariance), per-landmark improvement after first sighting, and translation invariance (`offset_map` == `baseline`). These checks were validated by re-injecting the angle-wrap bug, the old landmark seeding, and a bearing sign error, and for 3D the old `atan2(dz, dx) - yaw` elevation, a seeding that ignores elevation, and a filter that ignores pitch rate — each fails several of them. Standard EKF-SLAM is known to become somewhat overconfident about the global heading (worst-of-10-seeds NEES reaches the hundreds on some scenarios), so the NEES bound is tuned for the seeded runs rather than as a universal guarantee.
